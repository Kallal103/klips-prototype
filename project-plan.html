2 Delivery Phases

The build is structured in 7 phases across 8 weeks. Each phase has clear deliverables and exit criteria before progressing.

PHASE 0Pre-Build PrerequisitesBefore Week 1

These must be completed before development begins.

✓ SoW-001 signed and executed
✓ JWX SaaS agreement executed
✓ JWX API sandbox credentials provisioned
✓ Publisher tier structure confirmed
✓ Publisher and domain list provided (200+)
PHASE 1Discovery & SetupWeek 1

Kickoff, API exploration, environment provisioning, and design begins.

✓ RACI matrix and governance schedule
✓ JWX API integration design document
✓ Working staging environment with CI/CD
✓ Publisher portal wireframes (Figma)
✓ Prioritized product backlog
✓ QA test plan
Exit: Staging live, API verified, backlog ready, design in progress.
PHASE 2Publisher PortalWeeks 2–3

Core publisher-facing features — login, content discovery, and embed retrieval.

✓ Secure authentication (login, invite, password reset) for 200+ publishers
✓ Tiered content discovery with filters (broadcaster, type, recency, search)
✓ Embed code retrieval with preview (single clips and playlists)
Exit: Publishers can log in, browse tiered content, and copy embed codes on staging. Demo to client.
PHASE 3Admin Portal & IntegrationWeeks 4–5

Administration layer — publisher management, access control, and domain security.

✓ Publisher and tier management (create, edit, assign, bulk operations)
✓ Role-based access control (super admin, broadcaster, publisher)
✓ Domain whitelisting — embeds restricted to registered domains only
✓ JWX API integration layer (caching, rate limiting, error handling)
Exit: Admin can manage publishers, assign tiers, whitelist domains. RBAC enforced. Demo to client.
PHASE 4Broadcaster Reporting & PolishWeek 6

Broadcaster-facing analytics and overall quality improvements.

✓ Broadcaster reporting view — per-publisher consumption (each broadcaster sees only their data)
✓ Bug fixes from QA testing
✓ UI polish, responsive design, edge case handling
Exit: All three portals fully functional. No critical defects. Production environment ready.
PHASE 5Quality Assurance & UATWeek 7

Comprehensive testing followed by your team's walkthrough and acceptance.

✓ End-to-end functional testing across all portals
✓ Tier access verification (3 tiers × 4 broadcasters)
✓ Domain whitelisting enforcement testing
✓ Cross-browser and performance testing
✓ Client UAT walkthrough with your team
Exit: No Sev-1 or Sev-2 defects. Core journeys demonstrable. Client sign-off.
PHASE 6Migration, Training & Go-LiveWeek 8

Phased publisher migration, team training, and production launch.

✓ Publisher migration in 3 batches (Premium → Preferred → Open Exchange)
✓ Domain registration for all migrated publishers
✓ Admin team training with recorded sessions and playbooks
✓ Publisher onboarding materials (walkthrough guide, video tutorial, FAQ)
✓ Production go-live with 48-hour monitoring
Exit: 200 publishers migrated, admin team trained, production live, monitoring in place.

5 How We Work

⚙

Weekly Sprints

1-week sprints with planning on Monday and continuous delivery. Short cycles mean faster feedback and course correction.

▶

Biweekly Demos

Live demos of working features every 2 weeks (Weeks 3, 5, 7). You see real progress, not slides.

🔒

Quality Gates

Every feature passes code review, automated tests, and QA before reaching staging. No shortcuts to production.

🚀

Staging First

All features deploy to a staging environment that mirrors production. You test on staging before anything goes live.

🛡

Phased Migration

Publishers migrate in 3 batches (Premium → Preferred → Open). Existing embeds keep working during transition.

⚠

Post-Launch Warranty

4-week warranty after go-live covers defect resolution at no extra cost. Ongoing support under SoW-002.
